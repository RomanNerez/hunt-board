# company-types Specification

## Purpose

Довідник типів компаній (продуктова, аутсорс, аутстаф тощо), яким користувач позначає модель бізнесу компанії-роботодавця.

## Requirements

### Requirement: Тип компанії має унікальну назву
Система SHALL зберігати тип компанії з обов'язковою назвою до 255 символів. Система MUST NOT допускати два типи з однаковою назвою.

#### Scenario: Створення типу
- **WHEN** автентифікований користувач створює тип «Аутстаф»
- **THEN** система зберігає тип «Аутстаф»

#### Scenario: Тип без назви відхиляється
- **WHEN** користувач намагається зберегти тип з порожньою назвою
- **THEN** система відхиляє збереження з помилкою валідації поля назви

#### Scenario: Дублікат назви відхиляється
- **GIVEN** існує тип «Аутсорс»
- **WHEN** користувач створює ще один тип «Аутсорс»
- **THEN** система відхиляє збереження з помилкою валідації поля назви

### Requirement: Сторінка типів у розділі Налаштування
Адмін-панель SHALL мати сторінку «Типи компаній» у розділі «Налаштування» за адресою `/admin/settings/company-types` зі списком типів, пошуком за назвою, створенням, редагуванням і видаленням у модальних вікнах. Пункт MUST NOT з'являтися в головній навігації.

#### Scenario: Сторінка в субнавігації налаштувань
- **WHEN** користувач відкриває `/admin/settings/company-types`
- **THEN** у субнавігації розділу «Налаштування» є активний пункт «Типи компаній»
- **AND** у головній навігації немає пункту «Типи компаній»

#### Scenario: Пошук типу
- **GIVEN** існують типи «Продуктова» і «Аутсорс»
- **WHEN** користувач шукає «Аут»
- **THEN** у списку лише «Аутсорс»

### Requirement: Компанія має не більше одного типу
Компанія SHALL мати нуль або один тип із довідника. Форма компанії SHALL дозволяти обрати тип зі списку з пошуком і створити новий тип, не залишаючи форми.

#### Scenario: Вибір типу для компанії
- **GIVEN** існує тип «Продуктова»
- **WHEN** користувач обирає для компанії «MacPaw» тип «Продуктова» і зберігає її
- **THEN** компанія «MacPaw» має тип «Продуктова»

#### Scenario: Створення типу з форми компанії
- **WHEN** користувач у формі компанії створює новий тип «Стартап»
- **THEN** тип «Стартап» з'являється в довіднику
- **AND** його обрано для поточної компанії

### Requirement: Видалення типу, який використовують компанії
Під час видалення типу система SHALL зберігати компанії цього типу, лишаючи їх без типу.

#### Scenario: Видалення використовуваного типу
- **GIVEN** компанія «EPAM» має тип «Аутсорс»
- **WHEN** користувач видаляє тип «Аутсорс»
- **THEN** тип «Аутсорс» видалено
- **AND** компанія «EPAM» існує і не має типу
