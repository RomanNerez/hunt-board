# Spec Delta

## MODIFIED Requirements

### Requirement: Досвід резюме
Система SHALL зберігати для резюме довільну кількість записів про досвід роботи з обовʼязковими `company`, `position`, `start_date` та необовʼязковими `company_url`, `location`, `employment_type`, `end_date`. Поле `position` SHALL означати загальну роль у компанії. Запис SHALL належати рівно одному резюме й MUST видалятися разом із ним. Порожня `end_date` SHALL означати, що робота триває досі. Запис MUST NOT мати власного опису чи технологій: їх описують проєкти запису.

#### Scenario: Додавання завершеної роботи
- **GIVEN** користувач редагує резюме
- **WHEN** він додає запис із компанією «MacPaw», посадою «Senior PHP-розробник», початком 03.2021 і завершенням 08.2024 та зберігає
- **THEN** система зберігає резюме із цим записом, а `start_date` дорівнює 2021-03-01

#### Scenario: Поточна робота
- **WHEN** користувач зберігає запис без дати завершення
- **THEN** запис зберігається з порожньою `end_date`

#### Scenario: Запис без обовʼязкових полів
- **WHEN** користувач зберігає запис з порожньою компанією, посадою або датою початку
- **THEN** система відхиляє збереження з помилкою валідації відповідного поля
- **AND** жодні зміни резюме не зберігаються

#### Scenario: Некоректний період
- **WHEN** користувач зберігає запис, де дата завершення раніша за дату початку
- **THEN** система відхиляє збереження з помилкою валідації поля дати завершення

#### Scenario: Видалення резюме
- **GIVEN** резюме має два записи досвіду
- **WHEN** резюме видаляється
- **THEN** обидва записи теж видаляються

#### Scenario: Форма без опису й технологій
- **WHEN** користувач відкриває запис досвіду у вкладці «Досвід»
- **THEN** форма запису не має полів «Опис ролі» й «Технології»

## REMOVED Requirements

### Requirement: Опис ролі
**Reason**: Опис тепер задається окремо для кожного проєкту запису досвіду (див. `resume-experience-projects`, вимога «Опис проєкту»).
**Migration**: Резюме ще не в продакшені, тож наявні описи не переносяться. Локальну базу перестворюють через `migrate:fresh`.

### Requirement: Технології досвіду
**Reason**: Стек тепер задається окремо для кожного проєкту запису досвіду (див. `resume-experience-projects`, вимога «Стек проєкту»).
**Migration**: Резюме ще не в продакшені, тож наявні привʼязки технологій не переносяться. Локальну базу перестворюють через `migrate:fresh`.
